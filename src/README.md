# Sheets Leads Bot

Универсальный бот выгрузки лидов: следит за новыми строками в Google Таблицах и шлёт их в привязанные Telegram-группы. Один бот — сколько угодно клиентов. Вся настройка — в конфиг-таблице и командах, без правки кода.

## Как это работает

1. Есть **мастер-таблица** (конфиг). Лист называется `config`, первая строка — заголовки:

   | spreadsheet_id | sheet_name | chat_id | label | template | enabled |
   |---|---|---|---|---|---|
   | 1AbC...xyz | Лист1 | -1001234567890 | Клиент Киев | | TRUE |

   - `template` можно оставить пустым — тогда бот шлёт все заполненные поля строки в формате «Заголовок: значение». Или задать свой текст с плейсхолдерами: `Новый лид: {Имя}, тел. {Телефон}, город {Город}`
   - `enabled` — TRUE/FALSE, можно временно выключать клиента

2. Бот раз в `POLL_INTERVAL` секунд проверяет все активные таблицы. В каждой таблице он сам создаёт служебную колонку `tg_sent` и помечает отправленные строки временем отправки. Строка без отметки = новая заявка → уходит в группу. При первом подключении таблицы вся её история помечается как отправленная (в группу не сыпется).

3. Команды в группе клиента:
   - `/leads 10` — показать последние 10 заявок
   - `/bind <spreadsheet_id> <имя_листа> [название]` — привязать таблицу к этой группе (только админ). Строка в конфиг добавится сама
   - `/unbind` — отключить выгрузку в группу
   - `/id` — показать chat_id группы

4. Команды для тебя (в личке с ботом):
   - `/status` — все клиенты и их состояние
   - `/reload` — перечитать конфиг после ручных правок в таблице

## Настройка с нуля

### 1. Бот
- В @BotFather: `/newbot` → получить `BOT_TOKEN`
- Там же: `/setprivacy` → Disable (чтобы бот видел команды в группах)

### 2. Google
- Используй существующий сервисный аккаунт или создай новый в [console.cloud.google.com](https://console.cloud.google.com) (IAM → Service Accounts → Create → Keys → JSON)
- Включи **Google Sheets API** в проекте
- Из JSON-ключа нужны `client_email` и `private_key`
- **Каждую таблицу** (конфиг + все клиентские) расшарь на email сервисного аккаунта с правами **Редактор** (бот пишет отметки `tg_sent`)

### 3. Конфиг-таблица
- Создай таблицу, лист переименуй в `config`, вбей заголовки из таблицы выше
- ID таблицы — из URL: `docs.google.com/spreadsheets/d/`**`ВОТ_ЭТА_ЧАСТЬ`**`/edit`

### 4. Локальный запуск (проверка)
```bash
npm install
cp .env.example .env   # заполнить значения
npm start
```

## Деплой на Railway

1. Залей проект в приватный репозиторий GitHub:
   ```bash
   git init && git add . && git commit -m "init"
   git remote add origin git@github.com:ТВОЙ_ЛОГИН/sheets-leads-bot.git
   git push -u origin main
   ```
2. В [railway.app](https://railway.app): **New Project → Deploy from GitHub repo** → выбрать репозиторий
3. В сервисе открой вкладку **Variables** и добавь:
   - `BOT_TOKEN`
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `GOOGLE_PRIVATE_KEY` — вставляй значение из JSON целиком, вместе с `\n` внутри строки
   - `CONFIG_SPREADSHEET_ID`
   - `ADMIN_IDS` — твой Telegram id (узнать: @userinfobot)
   - `POLL_INTERVAL` — например `45`
4. Railway сам определит Node и запустит `npm start`. Дальше каждый `git push` = автодеплой
5. Проверь логи (вкладка Deployments → View Logs): должно быть `Конфиг загружен` и `Polling started`

## Подключение нового клиента (рутина)

1. Добавь бота в группу клиента (можно дать права админа, но не обязательно)
2. Напиши в группе: `/bind <id_таблицы> <имя_листа> Название_клиента`
3. Убедись, что таблица расшарена на сервисный аккаунт — если нет, бот сам скажет

Всё. Ни кода, ни редеплоя.
